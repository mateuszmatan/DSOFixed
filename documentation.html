12 Supported deployment targets

VM deployment via SSH (deployTarget: vm)

Default target. The library:

  1. Verifies SSH connectivity (ssh ... uptime)
  2. Creates the deploy directory on the remote host
  3. Copies deployScript and versionFile via SCP
  4. Executes deployScript on the remote host
  5. Verifies the deployed version by reading APP_VERSION from versionFile

Requirements: Jenkins agent must have SSH key-based access to the deployment host. deployScript must exist in your project. versionFile must contain APP_VERSION=<version>.

OpenShift deployment (deployTarget: openshift)

Uses the OpenShift Jenkins Plugin. The library:

  1. Reads cluster URL and credentials from deploy.openshift.<env>
  2. Applies deployConfig.yml from your repository root via openshift.process()
  3. Restarts the deployment rollout
  4. Waits for rollout to complete

Requirements: OpenShift Client Plugin installed. Cluster credentials in Jenkins with the configured credentialsId. deployConfig.yml in your repository root.

13 Advanced — using library methods directly

For projects with custom pipeline requirements you can call individual library methods from a hand-crafted Jenkinsfile. After loading the library, use devSecOpsPipeline as a method object:

@Library('DevSecOpsJenkinsLibrary') _

pipeline {
    agent any

    environment {
        SA_LINUX_URL       = 'https://tools.bbh.com/nexus/repository/releases/...'
        PROXY_HOST         = 'tstproxy.bbh.com'
        PROXY_PORT         = '9090'
        PROXY_USER         = 'PROXY_ASOCJenk'
        APPSCAN_HOST       = 'bbh.cloud.appscan.com'
        APPSCAN_SERVER_URL = 'https://bbh.cloud.appscan.com'
        APPSCAN_TOOLS_DIR  = "${WORKSPACE}/.appscan-tools"
        APPSCAN_LOG_DIR    = "${WORKSPACE}/.appscan-logs"
        APPSCAN_HOME_DIR   = "${WORKSPACE}/.appscan-home"
        APPSCAN_BIN_DIR    = "${WORKSPACE}/.appscan-bin"
    }

    stages {
        stage('Init') {
            steps { script {
                checkout scm
                devSecOpsPipeline.initialize()
                devSecOpsPipeline.appscanSetup()
                def projects = devSecOpsPipeline.getProjects()
                for (p in projects) {
                    devSecOpsPipeline.switchProject(p)
                    devSecOpsPipeline.appscanResolveSourceDir()
                    devSecOpsPipeline.appscanGenerateIRX()
                }
                devSecOpsPipeline.appscanLogin()
            }}
        }
        stage('Build & Scan') {
            steps { script {
                devSecOpsPipeline.buildArtifact()
                devSecOpsPipeline.unitTests()
                devSecOpsPipeline.checkCoverage(60)
                devSecOpsPipeline.depVulnScan()
                devSecOpsPipeline.codeQualityScan()
                devSecOpsPipeline.appscanQueue()
                devSecOpsPipeline.appscanWait()
                devSecOpsPipeline.appscanDownloadReports()
                devSecOpsPipeline.appscanEnforcePolicy()
            }}
        }
    }
    post { always { script {
        devSecOpsPipeline.generateHtmlReport()
        devSecOpsPipeline.feedInfluxDB()
    }}}
}

14 Troubleshooting

"config.yaml not found in workspace"

Your project repository must have a config.yaml at its root with a projects: section. Make sure it is committed and the branch is correct.

"asoc.keyId and asoc.keySecret must be set in config.yaml"

Every project entry must include:

asoc:
  keyId:     "bbh_..."
  keySecret: "..."

Obtain API credentials from the HCL AppScan on Cloud portal under your organization's API key settings.

"IRX not found after prepare"

  • The Gradle/Maven compile during IRX generation failed. Check .appscan-logs/prepare.log.
  • Ensure the Gradle wrapper (gradlew) is executable and committed. The library runs chmod +x gradlew automatically on Linux.

SAST stage times out

The default sast.pollTimeoutMin is 50 minutes — a library-level setting only the library team can change. IRX generation can take 10–20 minutes on large projects before polling even starts.

"SonarQube server not configured"

Register the SonarQube server in Jenkins under Manage Jenkins → Configure System → SonarQube servers with the name SonarQube (exactly this string).

Nexus IQ shows 0 vulnerabilities but build is UNSTABLE

The Jenkins sandbox may have blocked direct access to the scan result object. The library has a fallback that parses the console log. If that also fails, counts remain 0 but the build result set by the Nexus IQ plugin is still respected.

HTML report shows "Report could not be generated"

The pipeline failed before initialize() completed. A minimal fallback HTML is always written. Check the console output of stage 1 for the root cause.

"No test jobs configured — tests are mandatory"

All three test stages require at least one entry in their jobs: list. Use job: "" with type: local to create a placeholder entry that shows NOT_CONFIGURED without failing. If the jobs: list itself is empty or missing the stage fails.

Nexus delivery and QC deployment were skipped

The release gate compares the scan results and the line coverage with the library policy in resources/defaults.yaml. A project may raise its own thresholds for SAST, SCA, Nexus IQ and coverage in config.yaml, which lets the build reach the RD environment, but while the library policy is exceeded the artifact is not published to Nexus and QC is blocked. The build becomes UNSTABLE and the Release policy card of the HTML report lists every violation.

DAST PDF report is missing in the pipeline report

The DAST stage downloads the report as HTML and as PDF (appscan-dast-report-<scan>.pdf) and archives both. If only the HTML link is shown, check the console for [DAST] PDF report not found — generating the PDF in ASoC may have taken longer than the download window, or the report request returned no id.

GoldenFix pull request was not raised

The Nexus IQ GoldenFix card of the HTML report shows the reason. NOT_CONFIGURED — set scm.bitbucket.url and scm.bitbucket.credentialsId. NO_FIXES — Nexus IQ has no remediation version for the violating direct dependencies. NO_MANIFEST_CHANGES — the vulnerable versions are not declared in pom.xml, Gradle, package.json or pip files (e.g. managed by a BOM). ERROR — check the [GOLDENFIX] lines in the console log (Nexus IQ / Bitbucket permissions, push rights to the repository).

Many smoke tests (hundreds of jobs)

All jobs are executed even when some fail; at most tests.maxParallel (default 20) run at the same time. Remote jobs can be listed by full URL (url: or tests.smoke.urls) and share settings through tests.smoke.defaults. Increase maxParallel only if the remote Jenkins instances have enough executors.

Deploy stage fails with SSH permission denied

The Jenkins agent needs key-based SSH access to the deployment host. Add the agent's public key to ~/.ssh/authorized_keys on the target server and ensure StrictHostKeyChecking is not blocking the connection (the library passes -o StrictHostKeyChecking=no).
